# ALOS-Radiometric-Calibration

ALOS PALSAR radiometric-terrain-correction geometry, ported from the
UAVSAR method of Simard, M.; Riel, B. V.; Denbina, M.; Hensley, S.
(2016), *"Radiometric Correction of Airborne Radar Images Over
Forested Terrain With Topography,"* IEEE Transactions on Geoscience
and Remote Sensing, 54(8), 4488-4500, and the accompanying
[`uavsar_calib.cpp`](https://github.com/simard-landscape-lab/UAVSAR-Radiometric-Calibration).

## Citation convention

Every piece of code in this repository falls into one of three
categories. The category is stated explicitly wherever the code
appears, and the same wording is used consistently throughout:

- **Category A -- directly reused/adapted from the original UAVSAR
  repository.** Cited as: *(Simard et al., 2016, `uavsar_calib.cpp`
  L\<line numbers\>)*. Example: the `(ranpix, azpix)` DEM-to-radar-
  coordinate mapping table (`.trans` files) consumed by
  `geocode.resample_backscatter_to_dem_grid` is generated by
  `uavsar_calib.cpp` itself -- that C++ code is not duplicated here.

- **Category B -- Python translation of Simard's UAVSAR logic,
  adapted for ALOS.** Cited as: *(this work, following Simard et al.
  2016 Eq. \<N\>)*. This applies wherever the underlying physical
  formula is identical to UAVSAR's (the look-vector components in
  `geometry.compute_nL_local_frame`, and the 3 x 3-gradient terrain
  normal in `geometry.compute_nE_horn`), but the inputs are ALOS-
  specific.

- **Category C -- genuinely new logic with no UAVSAR counterpart.**
  No citation to Simard is attached. This is the author's own
  contribution: all of `leader_file.py` and `img_file.py` (ALOS CEOS
  byte-offset parsing, based on the official JAXA format specification
  NEB-070062B), and the Doppler-centroid ground-to-radar geolocation in `geolocate.py`.

**Rule:** if a formula came from Simard's paper or code, cite it every
time it reappears, even briefly. If the formula is the author's own
(byte parsing, interpolation, ALOS-specific geometry), never attach
Simard's citation to it, even where it sits next to code that does.

## Process flow (current)

Leader/IMG field positions follow JAXA, "ALOS/PALSAR Level 1.1/1.5 Product
Format Description," NEB-070062B.

1. Leader File (leader_file.py, geolocate.py): 28 ECR state vectors 60 s apart;
   pitch and yaw; theta_ih polynomial (DSSR bytes 1887-2006, R in km);
   line/pixel spacing (DSSR 1687-1718); Doppler centroid fd = a + b*R
   (DSSR 1735-1766, R in km); yaw steering flag (DSSR 1831-1834) -> ESA = 0.
2. IMG file (img_file.py, backscatter.py): line time (bytes 45-48), slant
   range to 1st sample (117-120); sigma0 = 10*log10(I^2+Q^2) + CF - 32.0.
3. Geolocation (geolocate.ground_to_radar): each DEM cell -> (azimuth, range)
   by solving (P-G).V/|P-G| = -lambda*fd(R)/2 with cubic Hermite orbit
   interpolation. No empirical offsets.
4. Facet geometry (area_correction.compute_facet_area_and_theta_l): 3 x 3
   unweighted gradient (divisor 6, uavsar_calib.cpp lines 567-568; not Horn's
   weighted operator) for slope/aspect with atan(q/p) as in uavsar_calib.cpp; nL from Simard et al.
   2016 Eq. 11; theta_l = arccos(nE.nL); area = area_ref/|nE.nI|.
5. Ratio (area_correction.compute_gamma0_ratio): IDW averages onto the radar
   grid (uavsar_calib.cpp L730-745); ratio = (1/sin theta_ih) *
   (area_ref/areaRDC) / cos(theta_l); void if theta_l > 70 or < 15 deg;
   clipped to [0.001, 1000].
6. gamma0 = sigma0 * ratio.

Flight heading is computed by the caller from the interpolated velocity at
scene-centre time (about -14.02 deg for ALPSRP049750870, -14.04 deg for
ALPSRP237630880). There is no end-to-end driver yet; run_pipeline.py is
deprecated and exits immediately.

## Repository structure

- alos_rtc/leader_file.py: Leader File parsing (Category C)
- alos_rtc/img_file.py: IMG Signal Data Record parsing (Category C)
- alos_rtc/backscatter.py: I/Q to calibrated sigma0 (Category C)
- alos_rtc/geolocate.py: Doppler-centroid geolocation (Category C)
- alos_rtc/geometry.py: theta_ih, nE, nL, theta_l per point (Category B)
- alos_rtc/area_correction.py: vectorised facet geometry, gamma0 ratio (Category B)
- alos_rtc/geocode.py: DEPRECATED corner-based geocoding
- run_pipeline.py: DEPRECATED old driver (exits immediately)
- docs/verification.md: verification record
- analysis/: thesis and poster analysis scripts (see docs/analysis.md)
- docs/analysis.md: run modes, inputs, outputs and results of the analysis

## Analysis scripts (thesis and poster)

`analysis/` contains the scripts that produce the figures and tables of the
master's thesis and the TASTI 2026 poster: window integration with the
Eq. 14 weights, same-quantity regressions against ESA CCI AGB, a benchmark
against the ASF RTC product, spatial block bootstrap, cross-validation of the
angular exponent, and a convergence test of per-pixel correction on
oversampled facets. Run modes, inputs, log files and the results used in the
thesis are documented in [docs/analysis.md](docs/analysis.md). No data are
included.

## Errors found and fixed during development

1. Heading sign error: a reversed cross-product gave 194 deg instead of about
   -13.7 deg (that value was later superseded by the velocity-derived heading).
2. ECEF/local-frame mismatch: nL was rotated into ECEF while nE stayed local.
3. Invalid-pixel corruption in the original uavsar_calib.cpp (not this
   package), fixed with -100.0f resets. The only defect found in the C++ code.
4. Summer range pixel spacing hard-coded to 4.684 m instead of 9.369 m.
5. Linear interpolation of 60-s orbit vectors put the satellite 2.5-3.4 km
   too low; replaced by cubic Hermite interpolation.
6. Zero-Doppler geometry assumed; L1.1 is focused to fd = a + b*R.
7. Aspect via arctan2 instead of atan(q/p), reversing 47.5% of facet normals.
8. Line-time origin taken from the integer-millisecond stamp of the first line
   (rounded); the true origin, from a fit over all lines, is 0.43 ms later,
   i.e. azimuth coordinates were about 0.93 line too large. Fixed with
   img_file.read_line_times_fit().

## Known limitations (not yet addressed)

- GLO-30 heights are EGM2008 geoid heights. The `alos_rtc` package still uses them
  as ellipsoidal heights; the analysis scripts apply a constant EGM2008 undulation
  (N = -27.32 m at the scene centre) through `RTC_GEOID_SHIFT` (see docs/analysis.md).
- After fixes 1-8, a per-facet comparison with the ASF RTC product leaves a
  constant azimuth offset of +4.17 lines (1.94 ms, about 13 m, within the
  9.7 m RMS strip-mode accuracy reported by Shimada et al. 2009,
  doi:10.1109/TGRS.2009.2023909). It is uniform over a 3 x 3 split of the
  image (+4.11 to +4.24 lines) and does not vary with range, which rules out
  the Doppler range term and the geoid; its exact cause (about 1 Hz in the
  Doppler centroid, or a fixed offset in the line-time definition) cannot be
  separated with one scene. `analysis/final_eq14.py` applies it as an
  empirical timing calibration (`RTC_AZ_SHIFT`, default 4.17; `RTC_AZ_SHIFT=0`
  disables it); after it the residual is below 0.1 line in all nine blocks.
  The `alos_rtc` package itself applies no empirical offset. The range
  residual is 0.04 pixel after the geoid correction.
- The UAVSAR antenna-pattern term (antcor) is not applied.
- The vegetation-table branch of uavsar_calib.cpp (cos_flag) is not ported.
- DEM latitude spacing uses 111320 m per degree instead of ellipsoid radii.
